# G7 on the box: the sacrificial `mltest` volume

Goal (NAND-PHASE2.md, G7): stock reads pages that mainline wrote, mainline
reads pages that stock wrote, bit-identical, with no uncorrectable read; on
the real brcmnand write path; with mainline allowed to write **only** the
`mltest` volume (2 MiB, created and removed by stock) and free PEBs.
`/jffs` stays read-only all the time.

**PASSED on the box on 2026-10-08** (NAND-PHASE2.md, gate status); the
sequence had passed in the nandsim rehearsal first (gates `g7_*`).

## What is needed

| Item | Where (build host) | Notes |
|---|---|---|
| G7 itb | `$OUT/images-g7/ml-bootfs-g7.itb` (+ `ml-bootfs-g7.info`) | `nand/build-g7-image.sh`; the production kernel (checked identical: same `Image.lzo`, same rescue initramfs and `ROOTFS_URL`), DT with **only** `read-only` dropped from the `image` partition (checked); `loader` stays read-only |
| rootfs | `$OUT/images/rootfs.squashfs` + `.sha256` | the **production** rootfs, served as usual at `ROOTFS_URL` (no separate rootfs) |
| kit | `$OUT/images/nand-phase2-kit/` | static tools (run on stock 4.19 and mainline), scripts, patterns, `SHA256SUMS` |
| backup | `~/oe-tool/backup/nand-raw-20261008/` | plus the fresh raw dump of step 2 |

Why not the production itb with a switch: the production DT marks the
`image` partition read-only, so the MTD layer refuses every write whatever
the kernel parameters; that is a deliberate, independent barrier, and
`mtdparts=` on the command line does not override DT partitions here. The
G7 itb differs from production only in that one DT property; the kernel and
the rootfs are the same.

On the G7 itb the write switches are still off by default
(`FENCE_VOLUMES=` empty, `brcmnand.allow_write=0`): booted as is, it
behaves like phase 1. Expect, in that state, one `ubi0 error ... error -30`
plus a stack dump and `ubi0` switching to read-only mode in `dmesg` when
UBI first tries a background write (refused by the write fence): that is the
fence working, not a fault.

## Step 2 - mainline, read-only first

Trial-boot slot 1 from stock as usual (`bcm_bootstate 3; reboot`); the G7
itb boots the production rootfs from `ROOTFS_URL`. On **mainline**, as
root, kit copied to `/tmp/gtb/`:

```sh
cd /tmp/gtb && sha256sum -c SHA256SUMS
cat /proc/mtd                                       # loader + image
M=/dev/mtd$(sed -n 's/^mtd\([0-9]*\): .* "image"$/\1/p' /proc/mtd)
cat /sys/class/mtd/${M#/dev/}/flags                 # 0x400 set: writable in the DT (G7 itb)
cat /sys/module/brcmnand/parameters/allow_write     # N
cat /sys/module/ubi/parameters/fence                # (empty)
grep ' /jffs ' /proc/mounts                         # ubifs ro
free -m                                             # >= 700 MB free (two dumps in /tmp)
```

Fresh raw dump (the restore source if anything goes wrong; RESTORE.md),
then copy it off and delete it from the box:

```sh
nanddump --noecc --oob --bb=dumpbad -f /tmp/gtb/mtd1-image-raw-oob-preG7.bin $M
sha256sum /tmp/gtb/mtd1-image-raw-oob-preG7.bin     # copy off, verify the sha256 there, then:
rm /tmp/gtb/mtd1-image-raw-oob-preG7.bin
```

PEB snapshot (owner map + corrected dump, kept in `/tmp/g7`):

```sh
./mltest-mainline.sh before     # "before: 265289728 B, mltest = vol N, k mltest PEBs"
```

PASS: `allow_write` N, fence empty, `/jffs` ro, image writable, `before`
OK. FAIL (e.g. image not writable, `allow_write` Y): stop, `reboot` (back
to stock), send the outputs.

## Step 3 - mainline, fenced on `mltest` only

```sh
sed -i 's/^FENCE_VOLUMES=.*/FENCE_VOLUMES=mltest/' /etc/conf.d/gt-be98-jffs
grep -E '^(FENCE_VOLUMES|JFFS_MODE)=' /etc/conf.d/gt-be98-jffs   # mltest / ro
rc-service gt-be98-jffs restart
cat /sys/kernel/debug/ubi/ubi0/fence        # state active, volumes mltest:N, pebs ...
cat /sys/module/brcmnand/parameters/allow_write                  # Y
grep ' /jffs ' /proc/mounts                                      # still ubifs ro
./mltest-mainline.sh verify-a   # mainline reads stock's pattern A: OK
./mltest-mainline.sh flips      # stock-written pages read raw by mainline: G7-FLIPS PASS
./mltest-mainline.sh write-b    # writes pattern B, reads it back: OK, prints the counters
./mltest-mainline.sh flips      # now incl. the mainline-written pages: G7-FLIPS PASS
cp /tmp/g7/flips/flips.txt /tmp/gtb/g7-flips-mainline.txt
./mltest-mainline.sh status > /tmp/gtb/g7-fence-status.txt
dmesg | grep -E 'fence|ubi0|brcmnand|UBIFS' > /tmp/gtb/g7-dmesg-fence.txt
dmesg > /tmp/gtb/g7-dmesg-full.txt
rc-service gt-be98-jffs stop                # detach, allow_write=0, fence cleared
cat /sys/module/brcmnand/parameters/allow_write                  # N
./mltest-mainline.sh after      # PEB diff: "G7-PEBDIFF PASS: only mltest (vol N) and free PEBs changed"
cp /tmp/g7/pebdiff.txt /tmp/g7/pebmap.before /tmp/gtb/
rm -f /tmp/g7/*.data
```

Copy `/tmp/gtb/g7-*.txt`, `pebdiff.txt`, `pebmap.before` off the box,
then `reboot` (one-shot trial: back to stock).

/jffs: with `FENCE_VOLUMES=mltest` the service mounts it `-o ro` and never
remounts it; in addition the jffs2 volume is outside the fence, so UBI
refuses any write to it (LEB write/unmap -> `-EROFS`). In the rehearsal a
deliberate `mount -o remount,rw` was accepted by UBIFS, whose first write
was refused by the fence (`refused LEB unmap of volume 13`), and UBIFS
switched itself to read-only; nothing reached the flash. Do not try that on
the box.

PASS: fence `state active` with `volumes mltest:N` only; both `flips`
print `G7-FLIPS PASS` (at most 1 bitflip per 512-B sector); `allow_write` Y
only while fenced, N after `stop`; `verify-a` and `write-b` OK; fence
line `writes W erases E refused 0 scrub_refused 0` (the `mtd_gate ... refused`
counter may be non-zero from the read-only phase of step 2) (a non-zero `scrub_refused` alone
is not a failure: it means UBI wanted to scrub a PEB outside the fence and
was refused; report it); no `ecc_failures` increase
(`status` output); `after` prints `G7-PEBDIFF PASS`.

FAIL:
- `rc-service gt-be98-jffs restart` falls back to read-only (`fenced attach
  failed` in its output): nothing was written; send `dmesg`; stop.
- `verify-a` mismatch (mainline cannot decode stock's pages): **G7 NO-GO**.
  Do not run `write-b`. Collect the fence file and `dmesg` as above, plus
  the raw pages of the mltest PEBs (read-only):
  `for p in $(awk -v v=$(cat /tmp/g7/mltest.id) '$3=="vol" && $4==v {print $2}' /tmp/g7/pebmap.before); do nanddump -n --oob -s $((p*131072)) -l 131072 -f /tmp/gtb/peb$p.raw $M; done`;
  `rc-service gt-be98-jffs stop`; reboot; then step 4 without `remove`.
- `write-b` fails or reads back wrong: `rc-service gt-be98-jffs stop`
  immediately, collect as above (`gt-be98-nandtool pebmap $M` again for the
  new PEBs), run `after` anyway (it tells whether anything outside mltest
  changed), reboot; step 4 without `remove`.
- `after` prints `G7-PEBDIFF FAIL`: **stop everything** (a PEB outside
  mltest/free changed). Keep `/tmp/g7/*` (copy off `before.data`,
  `after.data`, `pebdiff.txt`), `dmesg`, the fence file; reboot to stock,
  run only `stock-nandinfo.sh` (read-only), do not remove mltest, do not
  restore without the owner's decision (RESTORE.md, from the step-2 raw
  dump).
- Anything unexpected at any point: `rc-service gt-be98-jffs stop` (or just
  `reboot`: `allow_write` and the fence are not persistent), then collect.

## Step 4 - stock checks, compares, removes

On **stock** (boots normally after the trial):

```sh
cd /tmp/gtb            # the kit again if /tmp was cleared
sha256sum -c SHA256SUMS
./stock-mltest.sh verify-b                          # stock reads mainline's pattern B: OK
./stock-mltest.sh flips                             # mainline-written pages, raw on stock: G7-FLIPS PASS
cp /tmp/g7/flips/flips.txt /tmp/gtb/g7-flips-stock.txt
```

From the build host:

```sh
ssh root@<stock> '/bin/busybox sh /tmp/gtb/stock-nandinfo.sh' > g7-stock-after.txt
ssh root@<stock> 'dmesg' > g7-stock-dmesg.txt
```

then:

```sh
sh g7-compare.sh g7-stock-before.txt g7-stock-after.txt <sha256 of ml-bootfs-g7.itb>
```

and, only if `verify-b` and the comparison passed:

```sh
./stock-mltest.sh remove
ubinfo -d 0 -N mltest      # "no such volume"
```

`g7-compare.sh` checks: same UBI volumes (mltest ignored) with the same
type, size, `corrupted` 0, no update marker; every static volume and the
dynamic ones other than jffs2/data/mltest (rootfs1, rootfs2, defaults)
with the same sha256 as in the baseline; `ecc_failures` and `bad_blocks`
unchanged; `corrupted PEBs: 0` in the attach log when present; no UBI or
UBIFS error lines. The baseline itself matches the backup for the slot
volumes (the backup's static volumes, from the rehearsal: metadata1/2
`51aa0cb2...`, bootfs2 `74efd23e...`; bootfs1 was the production itb at
backup time and is the G7 itb now).

PASS (G7 passed): `verify-b` OK; `flips` `G7-FLIPS PASS`; `G7-COMPARE PASS`; `/jffs` mounts rw on
stock as usual; after `remove`, `ubinfo` back to the baseline volume list.
Then flash the production itb back to vol 3 (until G8).

FAIL:
- `flips` FAIL with `verify-a`/`verify-b` OK (decodes, but more than 1
  flip per sector in fresh pages): G7 NO-GO pending analysis; keep mltest,
  send `/tmp/g7/flips/` (raw, ecc, flips.txt, pebmap).
- `verify-b` mismatch (stock cannot decode mainline's pages): **G7 NO-GO**.
  Do not remove mltest. Collect `dmesg`, the stock report, and the raw
  mltest PEBs as stock reads them:
  `M=/dev/mtd$(sed -n 's/^mtd\([0-9]*\): .* "image"$/\1/p' /proc/mtd); ./gt-be98-nandtool pebmap $M > pebmap.stock; for p in $(awk -v v=<mltest id> '$3=="vol" && $4==v {print $2}' pebmap.stock); do ./nanddump -n --oob -s $((p*131072)) -l 131072 -f peb$p.stock.raw $M; done`.
- `G7-COMPARE FAIL`: stop; send both reports, the comparison output, stock
  `dmesg`, and the step-3 files; no further NAND writes of any kind
  (including `remove`) until analysed.
