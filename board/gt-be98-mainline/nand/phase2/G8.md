# G8 on the box: the first mainline read-write session on /jffs

Goal (NAND-PHASE2.md, G8): one supervised mainline session with `/jffs`
read-write through the UBI write fence on `jffs2` only; afterwards stock
boots normally, UBI 0 corrupted, `/jffs` mounts read-write cleanly, the
static and slot volumes unchanged, `ubinfo` unchanged except jffs2 usage.

The whole sequence below passed in the nandsim rehearsal (gates `g8_*`,
`rehearsal/results-20261008.txt`); it has not been run on the box.

## What is needed

- **Boot image**: the rw-jffs itb already in vol 3 (`ml-bootfs-g7.itb`,
  sha256 `6a8170c5...`); no reflash. Booted as is it cannot write: the
  switches are off (`FENCE_VOLUMES=` empty, `brcmnand.allow_write=N`), the
  chip is fenced and nothing vouches for any write (G7 step 2 on the box:
  `allow_write` N, fence empty, `mtd_gate refused 0`, i.e. nothing even
  tried).
- **rootfs**: the production `rootfs.squashfs` built with this kit (it
  carries the hardened `gt-be98-jffs` stop path); sha256 in the build
  report.
- **kit**: `$OUT/images/nand-phase2-kit/` (adds `jffs-mainline.sh`,
  `stock-jffs-check.sh`), `SHA256SUMS` compared out of band.
- **Reports leave the box immediately**: stock's `/tmp` is RAM and is lost
  at every reboot, so every report below is produced over ssh straight
  into a file on the build host, never stored on the box first.

## Step 0 - stock: kit, baseline (straight to the build host)

On stock: kit in `/tmp/gtb`, `cd /tmp/gtb && sha256sum -c SHA256SUMS`.
From the **build host**:

```sh
ssh root@<stock> '/bin/busybox sh /tmp/gtb/stock-nandinfo.sh' > g8-stock-before.txt
ssh root@<stock> 'ls -laR /jffs' > g8-stock-jffs-before.txt
```

PASS: `g8-stock-before.txt` shows UBI 0 corrupted, `ecc_failures` 0,
volumes 1,2,3,4,5,6,10,11,13, bootfs1 `6a8170c5...`, bootfs2 `74efd23e...`,
metadata1/2 `51aa0cb2...`, rootfs2 `845308de...`, defaults `6bef1ec7...`,
rootfs1 `ad345847...` (the G7 after-report). FAIL: stop.

## Step 1 - mainline, read-only first

Trial-boot slot 1 (`bcm_bootstate 3; reboot`). On mainline, kit in
`/tmp/gtb`:

```sh
cd /tmp/gtb && sha256sum -c SHA256SUMS
cat /sys/module/brcmnand/parameters/allow_write     # N
cat /sys/module/ubi/parameters/fence                # (empty)
grep ' /jffs ' /proc/mounts                         # ubifs ro
free -m                                             # >= 700 MB free
M=/dev/mtd$(sed -n 's/^mtd\([0-9]*\): .* "image"$/\1/p' /proc/mtd)
```

Fresh raw dump (required by G8: the restore source; a restore would also
undo whatever stock changed since):

```sh
nanddump --noecc --oob --bb=dumpbad -f /tmp/gtb/mtd1-image-raw-oob-preG8.bin $M
sha256sum /tmp/gtb/mtd1-image-raw-oob-preG8.bin
```

Copy it off, check the sha256 on the build host, then
`rm /tmp/gtb/mtd1-image-raw-oob-preG8.bin`. Then:

```sh
./jffs-mainline.sh before      # PEB map + dump, jffs2 superblock sha, sha of every /jffs file
```

PASS: `allow_write` N, fence empty, `/jffs` ro, raw dump off the box,
`before` prints its summary. FAIL: `reboot`, stop.

## Step 2 - mainline, fenced on jffs2, /jffs read-write

```sh
sed -i -e 's/^FENCE_VOLUMES=.*/FENCE_VOLUMES=jffs2/' -e 's/^JFFS_MODE=.*/JFFS_MODE=rw/' /etc/conf.d/gt-be98-jffs
grep -E '^(FENCE_VOLUMES|JFFS_MODE)=' /etc/conf.d/gt-be98-jffs   # jffs2 / rw
rc-service gt-be98-jffs restart        # "Remounting /jffs read-write (fenced)"
./jffs-mainline.sh check               # G8-CHECK PASS (fence on jffs2 only, /jffs rw, allow_write Y)
gt-be98-save --local                   # "/jffs/mainline-os/state.tgz (N B) written to the NAND through the fence"
ls -la /jffs/mainline-os; cat /jffs/mainline-os/state.tgz.sha256
./jffs-mainline.sh test                # G8-TEST PASS
./jffs-mainline.sh loop 20             # 20 x 1 MiB write+sync+delete
./jffs-mainline.sh verify              # G8-VERIFY PASS: superblock and all stock files unchanged
./jffs-mainline.sh status > /tmp/gtb/g8-fence-status.txt
dmesg | grep -E 'fence|ubi0|brcmnand|UBIFS' > /tmp/gtb/g8-dmesg-fence.txt
dmesg > /tmp/gtb/g8-dmesg-full.txt
cd /
rc-service gt-be98-jffs stop           # sync, unmount, detach, allow_write=0, fence cleared
cat /sys/module/brcmnand/parameters/allow_write                  # N
ls /sys/class/ubi/                                               # no ubi0
cd /tmp/gtb && ./jffs-mainline.sh after   # G8-PEBDIFF PASS: only jffs2 and free PEBs changed
cp /tmp/g8/pebdiff.txt /tmp/g8/pebmap.before /tmp/gtb/
```

Copy `/tmp/gtb/g8-*.txt`, `pebdiff.txt`, `pebmap.before` off the box
(`scp` from the build host), then `reboot` (the switch edits live in the
RAM overlay: the next mainline boot starts with them off again).

PASS: `G8-CHECK`, `G8-TEST`, `G8-VERIFY`, `G8-PEBDIFF` all PASS;
`gt-be98-save --local` exits 0; fence line `refused 0` (a non-zero
`scrub_refused` is not a failure in itself: UBI wanted to scrub a PEB
outside jffs2 and was refused; report it); `ecc_failures` 0 in `status`;
no `UBIFS error` / `ubi0 error` in `g8-dmesg-full.txt`; after `stop`:
`allow_write` N and no ubi0.

FAIL (any of them): `cd /; rc-service gt-be98-jffs stop` immediately (or
`reboot`: nothing is persistent), then:
- `restart` falls back to read-only (`fenced attach failed`): nothing was
  written; send `dmesg`; stop.
- `test`/`loop`/`save` fail, or UBIFS errors: collect `status`, `dmesg`,
  `/proc/mounts`; run `after` anyway (it says whether anything outside
  jffs2/free changed); reboot; on stock only the read-only part of step 3
  (`read`, `stock-nandinfo.sh`), no `write`/`clean`.
- `verify` FAIL (superblock or a stock file changed) or `after` prints
  `G8-PEBDIFF FAIL`: **stop everything**. Keep `/tmp/g8/*` (copy
  `before.data`, `after.data`, `pebdiff.txt`, `files.*` off), `dmesg`, the
  fence file; reboot to stock, run only `stock-nandinfo.sh` (read-only, over
  ssh to the build host); no further writes; restore only on the owner's
  decision (RESTORE.md, from the step-1 raw dump).

## Step 3 - stock

On stock (normal boot after the trial), kit in `/tmp/gtb`:

```sh
cd /tmp/gtb && sha256sum -c SHA256SUMS
./stock-jffs-check.sh read      # G8-STOCK-READ PASS: /jffs rw, marker.bin, state.tgz OK, no UBI/UBIFS errors
./stock-jffs-check.sh write     # G8-STOCK-WRITE PASS: stock writes/reads/deletes a file on /jffs
```

From the build host:

```sh
ssh root@<stock> '/bin/busybox sh /tmp/gtb/stock-nandinfo.sh' > g8-stock-after.txt
ssh root@<stock> 'dmesg' > g8-stock-dmesg.txt
sh g7-compare.sh g8-stock-before.txt g8-stock-after.txt 6a8170c5e33c9cc066f553539cebeb6f90c5947c42e69fb5ebd50b16e3bee031
```

(`g7-compare.sh` is the stock report comparison of G7; jffs2 and data are
excluded from the volume hashes, everything else must be identical.)

Then, when everything passed: `./stock-jffs-check.sh clean` (removes
`/jffs/mainline-os/g8-test`; `state.tgz` stays and is what the mainline OS
applies at its next boot) and one more ordinary stock reboot with
`stock-nandinfo.sh` over ssh (stock still happy after its own reboot).

PASS (G8 passed): `G8-STOCK-READ PASS`, `G8-STOCK-WRITE PASS`,
`G7-COMPARE PASS` (volumes, hashes, `ecc_failures`, `bad_blocks`,
`corrupted PEBs: 0`, no UBI/UBIFS errors), stock's own services fine after
the extra reboot.

FAIL: stop; send all files; no further NAND writes of any kind (stock's own
`/jffs` use aside) until analysed. If `/jffs` does not mount on stock, do
not let stock (or anyone) reformat it; restoring the step-1 raw dump
(RESTORE.md) is the owner's decision.

## After G8

The switches stay off in the image (`FENCE_VOLUMES=` empty). Using
`/jffs` read-write routinely (validation step 5, the soak; then perhaps a
default) is a separate owner decision.
